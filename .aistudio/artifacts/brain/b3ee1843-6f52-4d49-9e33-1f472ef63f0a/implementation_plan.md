# Кастомный выбор периода на вкладке графиков

Добавление возможности выбора произвольного диапазона дат (кастомного периода) на второй вкладке приложения «Графики» с помощью интерактивного диалога календаря диапазона дат (DateRangePicker) и отображения активного фильтра в строке чипов.

## User Review & Critical Decisions

> [!IMPORTANT] Решения, согласованные с пользователем на этапе интервью:
> - **Способ выбора дат**: интерактивный календарь с выбором диапазона «от» и «до» (Material 3 `DateRangePicker`).
> - **Расположение в интерфейсе**: отдельный чип «Свой период» в общей строке фильтров времени (рядом с чипами «30 дней», «3 месяца», «1 год», «Всё время»).
> - **Индикация диапазона**: при выборе диапазона чип отображает конкретные даты (например, «📅 15.01 – 20.03»), а повторное нажатие открывает диалог для изменения периода.

---

## 1. Overview & Core Concept

- **Что делает**: Пользователь может на вкладке графиков нажать на чип «Свой период» (или чип с уже выбранными датами), открыть полноэкранный/диалоговый календарь выбора диапазона дат (DateRangePicker) и отфильтровать график замеров, динамику и блок статистики за любой произвольный интервал времени (например, двухнедельный спринт, отпускной месяц или индивидуальный цикл тренировок).
- **Целевая аудитория**: Пользователи, отслеживающие изменения тела за специфические интервалы (например, «марафон сушки с 1 по 25 октября», интервал между контрольными визитами к врачу/тренеру).
- **Ключевая ценность**: Устранение ограничений только фиксированными окнами (30 дней / 3 месяца / 1 год) и отдельными календарными месяцами; полный контроль над анализируемым периодом.

---

## 2. User Experience & Visual Design

- **Пользовательский сценарий (User Flow)**:
  1. Пользователь переходит на вкладку «Графики».
  2. В горизонтальной строке временных фильтров видит чипы: `30 дней`, `3 месяца`, `1 год`, `Всё время`, `Свой период` (с иконкой `DateRange` или `CalendarToday`).
  3. Нажатие на `Свой период` открывает стилизованный Material 3 `DatePickerDialog` с компонентом `DateRangePicker`.
  4. Пользователь выбирает начальную и конечную дату на календаре.
  5. По нажатию «Применить» диалог закрывается, чип становится активным и меняет текст на выбранный интервал (например, `10.02 – 28.02`), а график и статистика мгновенно пересчитываются строго по выбранному отрезку времени (включая весь конечный день до 23:59:59).
  6. При выборе любого другого чипа (например, `30 дней` или отдельного месяца) кастомный фильтр деактивируется, но сохранённый диапазон остаётся доступен для повторного включения в один клик.

- **Визуальное оформление и элементы**:
  - **Чип фильтра**: `FilterChip` с Material 3 токенами, гармонирующими с текущим дизайном приложения. При выбранном диапазоне отображается иконка календаря и компактный диапазон дат в формате `дд.ММ – дд.ММ` (или `дд.ММ.гг`).
  - **Диалог календаря**: `DatePickerDialog` с акцентными цветами темы (`primary` / `primaryContainer`), кнопками «Отмена» и «Выбрать».
  - **Статистика и график**: Блок `MetricStatCard` и график `BodyMetricChart` плавно обновляются с отображением дельты и экстремумов именно за выбранный пользователем интервал.
  - **Пустое состояние**: Если в выбранный произвольный диапазон не попадает ни одной записи, отображается дружелюбная плашка с предложением расширить диапазон или добавить замер за эти даты.

---

## 3. Key Product Decisions & Trade-Offs

- **Решение 1: Использование Material 3 DateRangePicker в DatePickerDialog**:
  - *Выбранный подход*: Стандартный компонент Material 3 Compose `rememberDateRangePickerState` и `DateRangePicker`.
  - *Почему*: Полная доступность, поддержка жестов, локализации на русский язык, встроенная валидация корректности дат (начальная дата не может быть позже конечной).
  - *Альтернативы*: Два отдельных диалога `DatePicker` для начала и конца — отклонены пользователем в вопросе как менее удобные.

- **Решение 2: Границы диапазона по времени (Start of Day vs End of Day)**:
  - *Выбранный подход*: Дата начала нормализуется на `00:00:00.000` выбранного дня, а дата окончания — на `23:59:59.999` (или начало следующего дня).
  - *Почему*: Замеры, сделанные вечером или в течение последнего дня диапазона, гарантированно попадут в выборку графика.

- **Решение 3: Интеграция в модель состояний (ViewModel)**:
  - *Выбранный подход*: Добавление состояния `customDateRange: StateFlow<ClosedRange<Long>?>` и нового элемента в перечисление временных фильтров `TimeFilter.CUSTOM("Свой период", null)`.
  - *Почему*: Чистая архитектура, реактивное обновление `chartEntries` через `combine` без дублирования бизнес-логики.

## 4. Technical Architecture & Data Strategy

### Архитектурная схема компонентов

```
┌───────────────────────────────────────────────────────────────┐
│                    BodyMetricsViewModel                       │
│  - allEntriesAscending: StateFlow<List<BodyMetricEntry>>      │
│  - selectedTimeFilter: StateFlow<TimeFilter> (.CUSTOM)        │
│  - customDateRange: StateFlow<Pair<Long, Long>?>              │
│  - chartEntries: StateFlow (фильтрация по диапазону)          │
└───────────────────────────────┬───────────────────────────────┘
                                │
               ┌────────────────┴────────────────┐
               ▼                                 ▼
┌──────────────────────────────┐  ┌─────────────────────────────┐
│        ChartsScreen          │  │    DateRangePickerDialog    │
│  - Горизонтальные чипы       │◄─┤  - DateRangePicker (M3)     │
│    (30 дн., ..., Свой период)│  │  - Кнопки Отмена / Выбрать  │
│  - График BodyMetricChart    │  └─────────────────────────────┘
│  - Статистика за период      │
└──────────────────────────────┘
```

### Модели и изменения:

1. **`BodyMetricsViewModel.kt`**:
   - Расширение `TimeFilter`:
     ```kotlin
     enum class TimeFilter(val titleRu: String, val days: Int?) {
         MONTH_1("30 дней", 30),
         MONTH_3("3 месяца", 90),
         YEAR_1("1 год", 365),
         ALL("Всё время", null),
         CUSTOM("Свой период", null)
     }
     ```
   - Добавление `_customDateRange = MutableStateFlow<Pair<Long, Long>?>(null)`.
   - В `chartEntries`: при выборе `TimeFilter.CUSTOM` фильтровать записи по условию `it.dateMillis in startMillis..endMillis`.
   - Методы `setCustomDateRange(startMillis: Long, endMillis: Long)` и очистки.

2. **`ChartsScreen.kt`**:
   - Добавление чипа `Свой период` в ряд `TimeFilter.values()`.
   - Отображение форматированного диапазона (например, `10.02 – 24.02`) на чипе при активном кастомном фильтре.
   - Диалог `CustomDateRangePickerDialog` с Compose Material 3 `DateRangePicker`.

3. **Тестирование**:
   - Модульные тесты на фильтрацию `chartEntries` по кастомному диапазону дат (включая проверку граничных значений времени дня) в `ExampleRobolectricTest.kt`.
   - Проверка компиляции и сборки через `compile_applet`.
