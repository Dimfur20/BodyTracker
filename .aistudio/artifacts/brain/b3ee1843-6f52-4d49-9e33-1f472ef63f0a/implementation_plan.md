# Резервная копия JSON и потоковый импорт архива Mi Fitness (Xiaomi)

Реализация новой системы компактного резервного копирования в формате JSON (только реальные данные пользователя без пустых файлов и дубликатов) и добавление полноценного модуля импорта данных из архива Mi Fitness (Xiaomi) со специализированным экраном инструкции, потоковым разбором ZIP-архива любого объёма без зависания интерфейса и окном предпросмотра сводки перед подтверждением.

## User Review & Critical Decisions

> [!IMPORTANT] Решения, согласованные с пользователем на этапе интервью:
> - **Формат экрана инструкции**: отдельный полноценный экран с пошаговыми инструкциями получения архива из Mi Fitness и кнопкой выбора файла.
> - **Расположение кнопок JSON**: добавление отдельных специализированных кнопок «Экспорт (JSON)» и «Импорт (JSON)» в блоке резервного копирования без удаления существующих функций CSV.
> - **Обработка роста из профиля Mi Fitness**: в окне сводки перед импортом отображается чекбокс «Обновить рост в профиле (X см)» для явного согласия пользователя.

## 1. Overview & Core Concept

- **Что делает**:
  1. **Резервная копия JSON**: экспортирует только актуальные, непустые замеры (вес, рост, объёмы тела) и настройки пользователя (возраст, целевой вес, напоминания) в файл с версионированием (`schema_version: 1`). При импорте выполняет умную дедупликацию по паре `(type, timestamp)`, разрешая конфликты по `updated_at`, и показывает сводку перед записью.
  2. **Импорт из Mi Fitness**: позволяет пользователю загрузить исходный ZIP-архив из Xiaomi Mi Fitness. Приложение потоково (без загрузки сотен мегабайт в оперативную память) находит файлы `*hlth_center_fitness_data.csv` и `*user_member_profile.csv`, извлекает все замеры веса (`Key == "weight"`) и рост, группирует их, определяет дубликаты и показывает детальную сводку (период, количество новых/пропущенных записей) перед применением в единой транзакции.
- **Целевая аудитория**: Пользователи, переходящие с фитнес-весов и браслетов Xiaomi (Mi Fitness / Zepp Life) на локальное приложение BodyMetrics, а также те, кто хочет надёжно переносить данные между устройствами.
- **Ключевая ценность**: Мгновенный перенос истории взвешиваний за несколько лет из экосистемы Xiaomi без ручного перебивания цифр, отсутствие пустых файлов и гарантированная защита от дублирования.

## 2. User Experience & Visual Design

- **Пользовательский сценарий (User Flows)**:
  1. **Экспорт и импорт JSON**:
     - В разделе «Резервное копирование и экспорт» на вкладке «Настройки» пользователь видит карточки:
       - «Резервная копия (JSON)» с кнопками «Экспорт в JSON» и «Восстановить из JSON».
       - Существующие карточки «Google Диск» и «CSV» сохраняются нетронутыми.
     - При экспорте создаётся файл `bodymetrics_backup_YYYYMMDD_HHmm.json`.
     - При импорте проверяется `schema_version`, отображается диалог со сводкой («Найдено: X записей, будет добавлено: Y, пропущено дубликатов: Z») и кнопками «Отмена» и «Применить».
  2. **Импорт из Mi Fitness**:
     - В настройках размещается яркая карточка «Импорт из Mi Fitness (Xiaomi)».
     - Нажатие открывает отдельный экран `MiFitnessImportScreen` с навигацией «Назад».
     - На экране отображается пошаговая карточка-инструкция (с акцентными иконками шагов и текстом из константы) и большая кнопка «Выбрать архив (.zip)».
     - При выборе файла отображается индикатор прогресса потокового чтения («Обработка архива Mi Fitness...»).
     - После завершения анализа открывается диалоговое окно подтверждения:
       - Период замеров (например, `14.04.2022 — 02.11.2026`).
       - Количество найденных замеров веса.
       - Количество новых записей для добавления.
       - Количество пропущенных дубликатов.
       - Если в архиве обнаружен профиль с ростом — чекбокс «Обновить рост (182 см)».
     - По нажатию «Импортировать» данные атомарно записываются в базу данных Room в одной транзакции, выводится Toast/Snackbar с успехом, и пользователь возвращается к дневнику/графикам.

- **Визуальные компоненты и доступность**:
  - Карточки в стиле Material Design 3 с `tonalElevation` и скруглением 20–22 dp.
  - Пошаговый таймлайн инструкции с бейджами шагов `1`, `2`, `3`, `4`.
  - Все интерактивные элементы имеют `minimumInteractiveComponentSize(48.dp)` и уникальные `testTag`.

## 3. Key Product Decisions & Trade-Offs

- **Решение 1: Потоковое чтение `ZipInputStream` вместо загрузки в память**:
  - *Выбранный подход*: Использование `ZipInputStream` с построчной фильтрацией `BufferedReader.readLine()`. Сразу отбрасываются строки без подстроки `"weight"`, парсинг JSON вызывается только для совпавших строк.
  - *Почему*: Файлы Mi Fitness могут весить 100–150 МБ и содержать более 1.5 млн строк других датчиков (пульс, шаги). Загрузка в память привела бы к `OutOfMemoryError` на Android. Потоковый разбор потребляет считанные килобайты памяти и выполняется на фоновом диспатчере `Dispatchers.IO`.

- **Решение 2: Дедупликация и сопоставление записей**:
  - *Выбранный подход*: Дубликатом считается запись с тем же `type` и тем же `timestamp` (секунды UTC). Если в базе уже есть замер на это время, при импорте JSON сравнивается `updated_at` (оставляется более свежая), а при импорте Mi Fitness существующая запись не перезаписывается без необходимости.
  - *Почему*: В Mi Fitness за один день может быть несколько взвешиваний (утро/вечер), поэтому ключ по секундам UTC гарантирует точность и предотвращает размножение записей при повторном импорте того же архива.

- **Решение 3: Единая транзакция Room**:
  - *Выбранный подход*: `appDatabase.withTransaction { dao.insertAll(...) }`.
  - *Почему*: Защита от частичной записи при сбое устройства или нехватке места.

### Модели данных

1. **`JsonBackupPayload`**:
   ```kotlin
   data class JsonBackupPayload(
       val schema_version: Int = 1,
       val created_at: String, // ISO-8601
       val settings: JsonBackupSettings?,
       val records: List<JsonBackupRecord>
   )

   data class JsonBackupRecord(
       val id: String,
       val type: String, // weight, height, waist, chest, etc.
       val value: Float,
       val unit: String,
       val timestamp: Long, // Unix seconds UTC
       val note: String? = null,
       val source: String = "manual", // manual, mifitness, backup
       val updated_at: Long
   )
   ```

2. **`MiFitnessParseResult`**:
   ```kotlin
   data class MiFitnessParseResult(
       val totalWeightRecordsFound: Int,
       val newRecords: List<BodyMetricEntry>,
       val duplicateCount: Int,
       val minDateMillis: Long?,
       val maxDateMillis: Long?,
       val profileHeightCm: Float?
   )
   ```
