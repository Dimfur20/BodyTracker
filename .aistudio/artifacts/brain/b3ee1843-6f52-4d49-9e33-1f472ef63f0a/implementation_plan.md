# Комплексная доработка приложения: валидация, безопасность, миграции и дедупликация

Масштабное обновление надежности, конфиденциальности и автономности приложения BodyMetrics без изменения существующего визуального стиля и ключевых пользовательских сценариев.

## Решения и подтверждения пользователя

> [!IMPORTANT]
> На этапе уточнения требований согласованы следующие ключевые решения:
> 1. **Биометрическая защита**: При отмене или ошибке аутентификации приложение отображает полноэкранный оверлей блокировки с кнопкой «Разблокировать» (не сворачивая принудительно приложение, что предотвращает конфликты с системными диалогами).
> 2. **Темп изменения веса**: Скользящий 7-дневный темп при нехватке записей (меньше 7 дней) рассчитывается по всем доступным точкам взвешивания, обеспечивая плавный старт без пустых экранов.
> 3. **Автономность (Offline-first)**: Полное удаление плагинов и зависимостей Firebase для 100% локальной работы на устройстве.

---

## 1. Обзор и цели доработки

Обновление направлено на исключение любых повреждений и рассинхронизаций данных при импорте, усиление приватности личных показателей здоровья и повышение отказоустойчивости локальной базы данных:

1. **Гарантированная валидация данных при импорте (CSV, JSON, Mi Fitness)**:
   - Использование эталонных констант `MetricValidationUtil`:
     - Вес: $20.0 \dots 500.0$ кг;
     - Рост: $50.0 \dots 300.0$ см;
     - Обхваты: $10.0 \dots 250.0$ см;
     - Возраст: $14 \dots 120$ лет.
   - Исключение `NaN`, $\le 0$, бесконечностей и значений вне диапазона без срыва всего импорта.
   - Подсчёт и вывод в диалоге/уведомлении количества отфильтрованных строк.
   - Для CSV: при нераспознанной дате строка пропускается (сегодняшняя дата не подставляется). При отсутствии роста подставляется последний известный рост пользователя из базы, а не хардкод 175 см.

2. **Точная дедупликация**:
   - CSV: исключение повторного добавления одинаковых записей по точному совпадению метки времени до секунды (`dateMillis / 1000L`).
   - Mi Fitness: дублем считается не только совпадение по времени, но и совпадение веса (с точностью до $0.1$ кг) в пределах 10 минут ($600$ секунд) от уже имеющейся записи.

3. **Строгий парсинг Mi Fitness**:
   - Фильтрация строк исключительно по строгому совпадению `Key == "weight"` в колонке `Key`. Если структура колонок не распознана, применяется защитный откат к поиску ключа.

4. **Миграции Room и версионирование схемы**:
   - Удаление опасного вызова `fallbackToDestructiveMigration()`.
   - Включение `exportSchema = true` в `@Database`.
   - Настройка `ksp { arg("room.schemaLocation", "$projectDir/schemas") }` для генерации JSON-схем в `app/schemas`.
   - База данных сохраняет версию 1. Гарантия сохранности данных при любых будущих обновлениях.

5. **Отмена удаления (Undo)**:
   - При удалении замера из журнала показывается `Snackbar` «Замер удалён» с кнопкой «Отменить» на 6 секунд. При нажатии запись восстанавливается с идентичными значениями.

6. **Безопасность и офлайн-режим**:
   - Тумблер в Настройках «Скрывать содержимое в списке приложений и запретить скриншоты» (`FLAG_SECURE`, по умолчанию выключен).
   - Тумблер в Настройках «Блокировка отпечатком или PIN-кодом устройства» (`androidx.biometric:biometric` с `BIOMETRIC_STRONG or DEVICE_CREDENTIAL`, по умолчанию выключен). Запрос при старте и после 1 минуты нахождения в фоне.
   - Полное удаление `firebase-bom`, `firebase-ai`, `firebase-appcheck`, плагина `com.google.gms.google-services` и `googleServices` блока из Gradle.
   - Безопасный экспорт: удаление временного файла из кэша после отправки в `Intent.ACTION_SEND`, ограничение `file_paths.xml` подпапкой `exports/`.
   - Включение базы `body_metrics_db` и настроек `sharedpref` в правила Android Auto Backup (`backup_rules.xml`, `data_extraction_rules.xml`).

7. **Алгоритмические улучшения**:
   - Расчёт темпа снижения веса по 7-дневному скользящему среднему (вместо сравнения первой и последней записей за 30 дней).
   - Подстановка последнего сохранённого роста пользователя по умолчанию в диалоге добавления нового замера.

## 3. Архитектура и поток данных

```
┌──────────────────────┐      ┌─────────────────────────┐
│ CSV / JSON / ZIP     │ ---> │ MetricValidationUtil    │ ---> Исключение NaN, <=0, вне диапазона
└──────────────────────┘      └─────────────────────────┘      (Подсчёт отклонённых строк)
                                           │
                                           ▼
                              ┌─────────────────────────┐
                              │    Дедупликация         │ ---> CSV: точный timestamp (UTC сек)
                              │  (Existing Records)     │ ---> Mi Fitness: dt <= 10 мин и |dw| <= 0.1 кг
                              └─────────────────────────┘
                                           │
                                           ▼
                              ┌─────────────────────────┐
                              │   AppDatabase (Room)    │ <--- exportSchema = true
                              │  (Без destructive mig)  │ <--- Сохранение схемы в app/schemas
                              └─────────────────────────┘
```

### Структура изменений по слоям:

1. **Gradle и манифест**:
   - `build.gradle.kts` (root & app): удаление плагина Google Services, удаление зависимостей Firebase; добавление `androidx.biometric:biometric:1.2.0-alpha05`, настройка KSP `room.schemaLocation`.
   - `AndroidManifest.xml`: добавление `USE_BIOMETRIC`, обновление правил бэкапа.
   - `res/xml/file_paths.xml`: изоляция подпапки `exports`.
   - `res/xml/backup_rules.xml` и `res/xml/data_extraction_rules.xml`: объявление включения базы и настроек.

2. **Слой данных и валидации**:
   - `MetricValidationUtil.kt`: методы для комплексной проверки записей перед сохранением.
   - `BodyMetricRepository.kt`: строгий парсер CSV без автоподстановки сегодняшней даты, использование последнего известного роста.
   - `JsonBackupManager.kt`: отсев некорректных записей по диапазонам и подсчёт пропущенных строк.
   - `MiFitnessArchiveParser.kt`: строгая проверка `Key == "weight"`, дедупликация с окном 10 минут и дельтой веса $\le 0.1$ кг, подсчёт пропущенных строк.

3. **Слой настроек и безопасности**:
   - `UserSettingsRepository.kt`: хранение флагов `isSecureScreenEnabled` и `isBiometricLockEnabled`.
   - `MainActivity.kt`: наследование от `FragmentActivity`, обработка `FLAG_SECURE`, таймер 1 минуты в фоне, запуск `BiometricPrompt`.

4. **Слой логики и UI**:
   - `GoalPredictionUtil.kt`: 7-дневное скользящее среднее для темпа изменения веса.
   - `BodyMetricsViewModel.kt`: обработка отмены удаления, трансляция счетчиков пропущенных записей, управление состоянием блокировки.
   - `MainScreen.kt`, `JournalScreen.kt`, `SettingsScreen.kt`: отображение Snackbar с отменой, переключатели безопасности, экран блокировки при необходимости.
